KUZ-28558 F2 再現テスト

スタッフサービス様「登録F完了ページ」の遷移日時が未記録の件。
F2 = 完了ページを LINE 紐付け無しで一度開くと、そのタグの localStorage に lineId: "" が保存され、以後 LINE 経由で来ても cookie の LINE ID が空文字で上書きされて完了ページのタグが送信されなくなる事象。

環境：本番（修正 PR #49 デプロイ済み）
フォーム用タグ
完了ページ用タグ
サービス

ケース A と B は別のユーザーで行ってください（A = テストユーザー1、B = テストユーザー2）。ダッシュボードの値で結果を判別できます。

事前準備

  1. テスト対象サービス・タグは上の表の通り（作成済み）。テスト前にダッシュボードで、テストユーザー1・2 の「登録F」「登録F完了ページ」のエンティティ値（回数・日時）を控えておく。
  2. Chrome のシークレットウィンドウで開く（ケースごとに新しいシークレットウィンドウにするのが確実）。または下の「リセット」を押す。
  3. DevTools（F12）を開き、Console と Network タブ（フィルタ：api/v1）を表示しておく。ページ下部の Debug panel でも同じ情報を確認できます。

リセット（kuzen 系 cookie / localStorage を削除）

ケース A（対照：正常系）

  1. リセットする。
  2. ① 登録フォームを ?line_id= 付きで開く
  3. フォームの「送信する → 完了ページへ」を押す。
  4. 完了ページの Debug panel を確認。

期待結果：cookie に LINE ID あり／localStorage の lineId = LINE ID／POST /api/v1/actions 送信あり。ダッシュボードで「登録F」「登録F完了ページ」両方の回数・日時が記録される。

ケース B（F2 再現）

  1. リセットする（または新しいシークレットウィンドウ）。
  2. ① 完了ページを LINE ID 無しで開く
    → Debug panel の localStorage lineId が ""（空文字）になることを確認。
  3. 完了ページの「手順ページへ戻る」→ ② 登録フォームを ?line_id= 付きで開く
    → cookie に LINE ID が入ることを確認。
  4. フォームの「送信する → 完了ページへ」を押す。
  5. 完了ページの Debug panel と Console の lineId、Network の POST /api/v1/actions を確認（5 秒ほど待つ）。
  6. 完了ページの「再読み込み」をもう一度押し、同じく確認。

判定：完了ページで lineId が LINE ID・actions 送信あり・ダッシュボードに両方記録 → 修正 OK。
lineId が空・actions 未送信なら F2 が残っている（NG）。
